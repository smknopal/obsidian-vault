## 6. Hash dengan PowerShell

  

**GUI dulu, command sebagai verifikasi.**

  

GUI: klik kanan file → Properties tidak menampilkan hash secara default,

sehingga PowerShell adalah cara utama untuk hashing di H1.

  

### 6.1 Hash Satu File

  

- **Tujuan:** memastikan integritas evidence sebelum analisis dimulai.

- **Command:**

  

```powershell

Get-FileHash -Algorithm SHA256 "PATH_FILE"

```

  

- **Arti parameter:** `-Algorithm SHA256` memilih algoritma hash sesuai

  standar chain-of-custody H1; argumen path menunjuk file yang dihash.

- **Output diharapkan:** tabel dengan kolom `Algorithm`, `Hash`, `Path`.

- **Verifikasi:** kolom `Algorithm` = `SHA256`; kolom `Path` sesuai file

  yang dituju; nilai `Hash` bukan string kosong.

- **Kesalahan umum:** path tanpa tanda kutip saat mengandung spasi;

  salah menunjuk ke folder alih-alih file.

- **Lokasi output:** hasil tampil di layar; catat manual ke

  `OUTPUT/HASH/`.

- **Catatan keamanan:** jalankan pada file di `WORKING`/`ORIGINAL`,

  jangan pernah menghitung hash sambil membuka/menjalankan file.

  

### 6.2 Hash Banyak File dalam Folder

  

- **Tujuan:** membuat baseline hash untuk seluruh isi satu folder

  evidence sekaligus.

- **Command:**

  

```powershell

Get-ChildItem "PATH_FOLDER" -File |

Get-FileHash -Algorithm SHA256

```

  

- **Arti parameter:** `-File` pada `Get-ChildItem` mencegah subfolder

  ikut diproses seolah file; hasil di-pipe ke `Get-FileHash`.

- **Output diharapkan:** satu baris hash per file dalam folder.

- **Verifikasi:** jumlah baris hasil sama dengan jumlah file di folder

  (cek dengan `Get-ChildItem "PATH_FOLDER" -File | Measure-Object`).

- **Kesalahan umum:** lupa `-File` sehingga subfolder ikut diproses dan

  memunculkan error.

- **Lokasi output:** layar konsol; teruskan ke Bagian 6.3 untuk ekspor.

- **Catatan keamanan:** pastikan folder yang dituju adalah `WORKING`

  atau `ORIGINAL`, bukan `INBOX` yang belum diverifikasi.

  

### 6.3 Ekspor Hash ke CSV

  

- **Tujuan:** menyimpan hash sebagai bukti dokumentasi yang dapat

  dilampirkan di laporan lomba.

- **Command:**

  

```powershell

Get-ChildItem "PATH_FOLDER" -File |

Get-FileHash -Algorithm SHA256 |

Export-Csv "PATH_OUTPUT\hashes.csv" -NoTypeInformation

```

  

- **Arti parameter:** `-NoTypeInformation` menghilangkan header tipe

  .NET pada baris pertama CSV agar file lebih bersih dibaca.

- **Output diharapkan:** file `hashes.csv` berisi kolom `Algorithm`,

  `Hash`, `Path`.

- **Verifikasi:** file CSV dapat dibuka; jumlah baris sesuai jumlah

  file; nilai hash tidak kosong.

- **Kesalahan umum:** folder `PATH_OUTPUT` belum dibuat sehingga

  `Export-Csv` gagal.

- **Lokasi output:** `OUTPUT/HASH/hashes.csv`.

- **Catatan keamanan:** jangan menimpa `hashes.csv` lama — tambahkan

  timestamp pada nama file bila hash diulang.

  

### 6.4 Membandingkan Hash ORIGINAL vs WORKING

  

- **Tujuan:** membuktikan file di `WORKING` identik dengan file di

  `ORIGINAL` sebelum analisis dianggap sah.

- **Command:**

  

```powershell

$original = (Get-FileHash -Algorithm SHA256 "PATH_ORIGINAL").Hash

$working  = (Get-FileHash -Algorithm SHA256 "PATH_WORKING").Hash

$original -eq $working

```

  

- **Arti parameter:** dua `Get-FileHash` terpisah menghasilkan nilai

  hash masing-masing file; operator `-eq` membandingkan string hash.

- **Output diharapkan:** `True` jika kedua file identik, `False` jika

  berbeda.

- **Verifikasi:** hasil `True`; bila `False`, jangan lanjutkan analisis

  sebelum penyebab perbedaan dicatat.

- **Kesalahan umum:** membandingkan file yang salah (mis. path

  `WORKING` menunjuk ke hasil ekstrak berbeda dari `ORIGINAL`).

- **Catatan keamanan:** `False` bukan berarti evidence rusak secara

  otomatis — catat sebagai temuan, verifikasi ulang path dan proses

  copy sebelum menyimpulkan integritas gagal.

  

Sebelum command final dipakai:

- verifikasi syntax pada PowerShell lokal;

- gunakan placeholder path (`PATH_FILE`, `PATH_FOLDER`, `PATH_OUTPUT`);

- jangan memasukkan path evidence fiktif seolah-olah nyata.

  

**VERIFIKASI**

- Hash berhasil muncul di layar.

- Kolom `Algorithm` menunjukkan `SHA256`.

- Kolom `Path` sesuai file yang dituju.

- Jumlah baris hash sesuai jumlah file.

- File `hashes.csv` dapat dibuka dan terbaca.

  

**TROUBLESHOOTING**

  

| Masalah | Kemungkinan Penyebab | Solusi |

|---|---|---|

| Path mengandung spasi | Path tidak diapit tanda kutip | Bungkus path dengan `"..."` |

| Permission denied | File terkunci proses lain / read-only | Tutup aplikasi lain, cek izin folder |

| File tidak ditemukan | Salah path atau file belum di-copy ke WORKING | Cek ulang path dan struktur folder |

| File masih di ZIP | Belum diekstrak | Ekstrak dahulu ke WORKING sebelum hash |

| Hash berubah setelah copy | File ter-modifikasi saat transfer / bukan file yang sama | Hash ulang di ORIGINAL dan WORKING, bandingkan |

## 7. Persiapan Evidence

  

Prosedur baku:

  

1. Terima file pada `INBOX`.

2. Catat nama file, ukuran, waktu penerimaan, dan sumber file.

3. Copy, bukan move, ke `ORIGINAL`.

4. Hitung SHA-256 file pada `ORIGINAL`.

5. Simpan hash ORIGINAL ke `OUTPUT/HASH`.

6. Copy file dari `ORIGINAL` ke `WORKING`.

7. Hitung SHA-256 file pada `WORKING`.

8. Bandingkan hash ORIGINAL dan WORKING.

9. Lanjutkan analisis hanya jika hasil perbandingan `True`.

10. Jika hasil `False`, hentikan analisis working copy, periksa path,

    copy ulang dari ORIGINAL, hitung ulang hash, dan dokumentasikan

    kejadian tersebut.

11. Lakukan seluruh analisis pada `WORKING`.

12. Simpan CSV, screenshot, notes, XML, dan export pada `OUTPUT`.

13. Jangan overwrite output lama.

  

```powershell

$OriginalHash = (Get-FileHash -Algorithm SHA256 "PATH_ORIGINAL").Hash

$WorkingHash  = (Get-FileHash -Algorithm SHA256 "PATH_WORKING").Hash

$OriginalHash -eq $WorkingHash

```

  

**Perbedaan penting:**

  

- **Copy vs Move** — copy mempertahankan file asal utuh; move berisiko

  kehilangan evidence asli jika terjadi kegagalan proses.

- **Extract ZIP vs membuka langsung** — buka arsip di WORKING agar file

  hasil ekstrak tidak tercampur dengan ORIGINAL.

- **Original evidence vs working copy** — ORIGINAL adalah rujukan hash;

  WORKING adalah tempat kerja yang boleh "kotor".

- **Event timestamp vs file system timestamp** — waktu di dalam event

  (`TimeCreated`) bukan waktu file EVTX di-copy/modifikasi di disk.

**Details — XML View** — bentuk mentah event, dipakai untuk memverifikasi:

  

- Provider

- EventID

- TimeCreated

- EventRecordID

- Channel

- Computer

- Subject fields

- Target fields

- EventData

  

**WAJIB PAHAM**

## 11. Event Viewer — Custom View dan XML Query

  

- **Custom View** menyimpan kombinasi filter agar dapat dipakai ulang.

- **XML Query** dipakai untuk kondisi lebih kompleks yang tidak bisa

  dibuat lewat form filter biasa.

- Event ID sebaiknya dikombinasikan dengan provider/channel yang tepat

  agar hasil tidak bercampur dari sumber lain.

  

**Contoh XML query sederhana (beberapa Event ID pada satu channel):**

  

```xml

<QueryList>

  <Query Id="0" Path="Security">

    <Select Path="Security">

      *[System[(EventID=4624 or EventID=4625 or EventID=4672)]]

    </Select>

  </Query>

</QueryList>

```

  

**KESALAHAN UMUM**

- Syntax XML sensitif terhadap tanda kurung dan operator `or`/`and`.

- Query yang salah dapat menghasilkan nol event tanpa pesan error yang

  jelas.

- Saved EVTX dan live log dapat memiliki konteks metadata berbeda

  (mis. Computer name saat live vs saat disimpan).

- Pada file EVTX yang dibuka lewat **Open Saved Log**, atribut `Path`

  pada XML Query tetap merujuk nama channel asal event (mis.

  `Security`), bukan nama file `.evtx` atau nama display yang diberikan

  saat membuka log — gunakan **Filter Current Log** pada log yang

  sudah terbuka agar query diterapkan ke tampilan saved log tersebut.

- Jangan mengubah hasil filter menjadi kesimpulan langsung — filter

  hanya alat bantu pencarian.

**Preflight sebelum menulis command:**

  

1. Cari executable `EvtxECmd.exe` yang sudah tersedia di folder tool.

2. Jalankan `EvtxECmd.exe -h` untuk melihat opsi yang valid pada versi

   lokal.

3. Catat versi tool.

4. Pastikan syntax command yang dipakai sesuai output Help tersebut.

5. Jangan memakai command dari internet tanpa verifikasi terhadap Help

   lokal.

  

**Fungsi utama:**

- Parse satu EVTX.

- Parse satu folder EVTX (batch).

- Output CSV.

- Mempertahankan metadata penting (source file, record id, timestamp).

- Membantu triage/analisis massal sebelum masuk Timeline Explorer.

## 14. EvtxECmd — Parse Satu File

  

**Format konseptual (verifikasi ulang terhadap Help lokal):**

  

```

EvtxECmd.exe -f "INPUT_EVTX" --csv "OUTPUT_FOLDER" --csvf "OUTPUT_FILE.csv"

```

  

Arti parameter:

- `-f` — path file EVTX input.

- `--csv` — folder tujuan output CSV.

- `--csvf` — nama file CSV output.

  

> Gunakan syntax yang ditampilkan oleh Help versi EvtxECmd yang

> terpasang. Dokumentasikan perbedaan bila opsi lokal berbeda dari

> contoh di atas.

  

**VERIFIKASI**

- File CSV tercipta di folder tujuan.

- Jumlah baris/record masuk akal dibanding jumlah event di Event Viewer.

- Kolom nama source file terlihat.

- Kolom Event ID terlihat.

- Kolom timestamp terlihat.

- Kolom Payload atau field penting lain tersedia.

- Tidak ada error parse yang serius di output console.

**TROUBLESHOOTING**

  

| Masalah | Penyebab mungkin | Solusi |

|---|---|---|

| Executable tidak ditemukan | Path salah / belum di-extract | Cek ulang lokasi tool |

| Quote hilang | Path mengandung spasi tanpa kutip | Bungkus path dengan `"..."` |

| Maps tidak ditemukan | Versi tool memerlukan file maps terpisah | Cek folder instalasi untuk file maps |

## 17. Timeline Explorer — Filter, Sort, dan Group

  

Praktik dasar:

  

- Filter Event ID.

- Filter berdasarkan user.

- Filter berdasarkan IP.

- Filter berdasarkan nama process.

- Filter keyword pada kolom Payload.

- Sort timestamp ascending.

- Group berdasarkan Event ID.

- Group berdasarkan user.

- Group berdasarkan source file.

- Reset filter ke kondisi awal.

- Periksa jumlah baris setelah filter diterapkan.

  

**Contoh fiktif (untuk latihan, bukan Guided Lab):**

  

- 4625 difilter berdasarkan `IpAddress`.

- 4624 difilter berdasarkan `TargetUserName`.

- 4688 difilter yang mengandung kata `powershell`.

- 7045 difilter berdasarkan `ServiceName`.

- 1102 difilter berdasarkan `TimeCreated`.

  

**VERIFIKASI**

- Jumlah baris berkurang secara konsisten setiap kali filter ditambah,

  bukan tiba-tiba nol.

- Hasil group menunjukkan total yang sama dengan jumlah baris sebelum

  di-group (tidak ada baris hilang).

- Sort ascending menghasilkan `Timestamp` paling awal di baris teratas.

  

**KESALAHAN UMUM**

- Filter kolom yang tertinggal aktif dari sesi sebelumnya sehingga hasil

  baru tampak salah padahal filter lama belum direset.

- Group diterapkan sebelum filter, sehingga hasil group mencampur data

  yang seharusnya sudah disaring lebih dulu.

- Menyimpulkan "tidak ada event" padahal filter keliru menunjuk kolom

## 20. PowerShell — Get-WinEvent

  

**Membuka EVTX offline:**

  

```powershell

Get-WinEvent -Path "PATH_FILE"

```

  

Filter Event ID menggunakan `FilterXPath` (kompatibel untuk offline EVTX

dengan parameter `-Path`).

  

Sebelum command dipakai final:

- uji syntax di PowerShell lokal;

- pastikan command bekerja dengan `-Path` (bukan `-LogName`, yang

  ditujukan untuk log live);

- jangan menggunakan `FilterHashtable` dengan kombinasi parameter yang

  tidak didukung bersama `-Path` pada versi PowerShell yang dipakai;

- gunakan placeholder path saat mendokumentasikan.

  

**Field output penting:**

- `TimeCreated`

- `Id`

- `ProviderName`

- `MachineName`

- `RecordId`

- `Message`

- `Properties`

- `.ToXml()`

  

**Melihat XML mentah dari satu event:**

  

```powershell

$event = Get-WinEvent -Path "PATH_FILE" | Select-Object -First 1

$event.ToXml()

```

  

**Menyimpan raw XML ke file (bukti dokumentasi):**

  

```powershell

$event = Get-WinEvent -Path "PATH_FILE" | Select-Object -First 1

$event.ToXml() | Out-File "PATH_OUTPUT\raw_event.xml" -Encoding utf8

```

  

- **Verifikasi:** file `raw_event.xml` terbuka dan berisi tag `<Event>`

  lengkap, bukan teks kosong.

- **Lokasi output:** `OUTPUT/EXPORT/` (ikuti naming convention Bagian 4).

- **Catatan keamanan:** raw XML hanya disimpan sebagai bukti baca,

  bukan untuk dieksekusi atau diproses ulang sebagai command.

  

**Ekspor hasil ke CSV:**

  

```powershell

Get-WinEvent -Path "PATH_FILE" |

Select-Object TimeCreated, Id, ProviderName, MachineName, RecordId, Message |

Export-Csv "OUTPUT.csv" -NoTypeInformation

```

  

> Ekspor langsung tanpa `Select-Object` menyertakan banyak properti

> .NET internal yang membuat CSV sulit dibaca; memilih kolom yang

> relevan (`TimeCreated`, `Id`, `ProviderName`, `MachineName`,

> `RecordId`, `Message`) menghasilkan CSV yang lebih mudah diperiksa

> manual atau dibuka di Timeline Explorer.

> Kolom `Message` dapat kosong jika resource/provider untuk merender

> pesan tidak tersedia di mesin analisis.

## 21. PowerShell — Pencarian Praktis

  

**Mencari Event ID tertentu**

- Tujuan: mengisolasi event spesifik dari file besar.

- Placeholder: `PATH_FILE`, `EVENT_ID`.

- Command: `Get-WinEvent -Path "PATH_FILE" -FilterXPath "*[System[EventID=EVENT_ID]]"`

- Output diharapkan: daftar event dengan ID tersebut saja.

- Verifikasi: seluruh baris `Id` sama dengan `EVENT_ID`.

- Kesalahan umum: XPath tanpa tanda kurung siku menghasilkan error syntax.

- Lokasi output: layar konsol; teruskan ke `Export-Csv` bila perlu disimpan.

- Catatan keamanan: hanya membaca file `.evtx` di `WORKING`, tidak

  memodifikasi file sumber.

  

**Mencari beberapa Event ID**

- Tujuan: mengisolasi beberapa ID sekaligus.

- Command: `Get-WinEvent -Path "PATH_FILE" -FilterXPath "*[System[(EventID=4624 or EventID=4625)]]"`

- Verifikasi: hanya dua nilai `Id` yang muncul.

- Kesalahan umum: lupa tanda kurung pembungkus kondisi `or`.

- Lokasi output: layar konsol.

- Catatan keamanan: sama seperti di atas — operasi baca saja.

  

**Membatasi waktu**

- Tujuan: mempersempit event ke jendela waktu investigasi.

- Command:

  ```powershell

  $Start = [datetime]"2026-07-21T20:00:00"

  $End   = [datetime]"2026-07-21T21:00:00"

  

  Get-WinEvent -Path "PATH_FILE" |

  Where-Object {

      $_.TimeCreated -ge $Start -and

      $_.TimeCreated -le $End

  } |

  Select-Object TimeCreated, Id, ProviderName

  ```

- `$Start` dan `$End` merupakan objek `DateTime`.

- Format ISO `YYYY-MM-DDTHH:mm:ss` mengurangi ambiguitas locale.

- Nilai tanggal dan waktu pada contoh bersifat fiktif.

- Waktu harus disesuaikan dengan timezone evidence.

- Timeline lintas host harus dinormalisasi sebelum dibandingkan.

- Jangan mengubah timezone sistem hanya agar timestamp terlihat sama.

- Expected output: hanya event dalam rentang `$Start` hingga `$End`;

  kolom `TimeCreated`, `Id`, dan `ProviderName` tampil.

- Verifikasi: periksa timestamp event pertama; periksa timestamp event

  terakhir; pastikan seluruh event berada dalam rentang; bandingkan

  hasil dengan filter Event Viewer.

- Kesalahan umum: membandingkan `TimeCreated` (objek `DateTime`) dengan

  string mentah tanpa cast `[datetime]` dapat menghasilkan perbandingan

  yang tidak konsisten tergantung locale.

- Lokasi output: layar konsol.

- Catatan keamanan: catat timezone yang dipakai saat menuliskan `$Start`

  dan `$End` agar tidak salah interpretasi saat dokumentasi.

  

**Mencari string pada Message**

- Tujuan: menelusuri event lewat kata kunci pada teks Message.

- Command: `Get-WinEvent -Path "PATH_FILE" | Where-Object { $_.Message -like "*KEYWORD*" }`

- Kesalahan umum: `Message` kosong sehingga pencarian tidak menemukan apa pun walau event ada.

- Lokasi output: layar konsol.

- Catatan keamanan: jangan menyalin keyword hasil pencarian menjadi

  perintah yang dijalankan ulang tanpa diperiksa.

  

**Melihat XML per event**

- Tujuan: memverifikasi nama field mentah saat label GUI meragukan.

- Command: `($event).ToXml()`

- Verifikasi: field yang dicari (mis. `TargetUserName`) muncul di teks XML.

- Lokasi output: layar konsol; salin ke notes bila jadi bukti.

- Catatan keamanan: `$event` harus hasil pemilihan dari `Get-WinEvent`

  sebelumnya, bukan diketik ulang manual.

  

**Ekspor CSV**

- Command: lihat Bagian 20.

- Verifikasi: file CSV terbuka dan kolom sesuai.

- Lokasi output: `OUTPUT/CSV/`.

- Catatan keamanan: gunakan nama file sesuai konvensi Bagian 4 agar

  tidak menimpa ekspor sebelumnya.

  

**Menghitung event per Event ID**

- Tujuan: triase cepat — Event ID mana yang paling sering muncul.

- Command: `Get-WinEvent -Path "PATH_FILE" | Group-Object Id | Sort-Object Count -Descending`

- Verifikasi: total count sesuai jumlah event di Event Viewer.

- Lokasi output: layar konsol.

- Catatan keamanan: hasil ini hanya gambaran frekuensi, bukan kesimpulan

  insiden — tetap perlu pivot dan correlation (Bagian 18, 26).

  

**Sort berdasarkan waktu**

- Tujuan: menyusun urutan kronologis sebelum membuat timeline.

- Command: `Get-WinEvent -Path "PATH_FILE" | Sort-Object TimeCreated`

- Verifikasi: urutan `TimeCreated` naik dari atas ke bawah.

- Lokasi output: layar konsol.

- Catatan keamanan: pastikan sumber `TimeCreated` sudah dalam timezone

  yang sama seperti dicatat di Bagian 1 (lihat file 01) sebelum dipakai

  untuk timeline lintas host.

## 22. wevtutil

  

Fungsi:

- Membaca EVTX offline dari command line.

- Query berdasarkan Event ID.

- Output dalam bentuk text atau XML.

- Membaca metadata log (jumlah record, ukuran).

  

Sebelum menulis command final, uji dengan:

  

```

wevtutil /?

wevtutil qe /?

```

  

Pastikan opsi untuk membaca file EVTX offline (mis. `/lf:true`) sesuai

dengan output Help pada versi Windows yang dipakai.

  

**JANGAN DILAKUKAN**

- Jangan memasukkan perintah `clear-log`.

- Jangan memasukkan perintah `set-log`.

- Jangan memasukkan perintah `delete`.

- Jangan memasukkan command apa pun yang memodifikasi evidence.

  

**COMBAT RULE**

> Pada materi ini, `wevtutil` hanya digunakan untuk query dan membaca

> (`qe`, `gli`), tidak untuk mengubah log.

  

### 22.1 Membaca seluruh EVTX offline sebagai XML

  

```cmd

wevtutil qe "PATH_FILE.evtx" /lf:true /f:xml /rd:false

```

  

- **Tujuan:** membaca seluruh event pada file EVTX offline dalam format

  XML agar mudah diperiksa field-nya.

- **Verifikasi:** output XML tampil di layar, jumlah blok `<Event>`

  masuk akal dibanding jumlah event di Event Viewer.

- **Catatan keamanan:** operasi baca saja; jangan menambahkan opsi

  `/c:` tanpa memahami efeknya pada jumlah event yang ditampilkan.

  

### 22.2 Query Event ID tertentu pada EVTX offline

  

```cmd

wevtutil qe "PATH_FILE.evtx" /lf:true /q:"*[System[(EventID=4624)]]" /f:text

```

  

- **Tujuan:** mengisolasi Event ID tertentu tanpa membuka Event Viewer.

- **Verifikasi:** setiap event pada output menunjukkan `EventID` 4624.

- **Kesalahan umum:** syntax XPath pada `/q:` sensitif terhadap tanda

  kurung; verifikasi ulang terhadap `wevtutil qe /?` pada versi lokal.

  

### 22.3 Membaca metadata log (read-only)

  

```cmd

wevtutil gli "PATH_FILE.evtx" /lf:true

```

  

- **Tujuan:** melihat metadata file EVTX (mis. jumlah record, ukuran)

  tanpa membuka isi event satu per satu.

- **Verifikasi:** field seperti jumlah record tampil dan masuk akal

  dibanding hasil Event Viewer.

- **Catatan keamanan:** `gli` bersifat baca saja; tetap dilarang

  menjalankan `sl` (set-log) atau opsi lain yang mengubah konfigurasi.

## 24. CyberChef Lokal

  

Kebutuhan H1 terbatas pada:

  

- From Base64

- Hex decoding

- URL Decode

- Defang/Refang URL atau IP

- Extract URLs

- Strings sederhana (jika tersedia)

- Memahami perbedaan input vs output

- Decode PowerShell `-EncodedCommand` (Base64 + UTF-16LE)

  

**Decode PowerShell `-EncodedCommand`:**

  

**Event ID 4688**

  

Event ID 4688 mencatat process creation. Jika command line auditing

aktif, field command line dapat menampilkan parameter

`-EncodedCommand` atau `-enc`.

  

Jika parameter tersebut ditemukan, nilai setelah parameter biasanya

merupakan Base64 yang merepresentasikan teks UTF-16LE.

  

**Event ID 4104**

  

Event ID 4104 mencatat script block yang diproses PowerShell jika

Script Block Logging aktif.

  

Konten 4104 kadang lebih mudah dibaca dibanding command line awal,

tetapi tidak menjamin:

  

- seluruh encoding berubah menjadi plaintext;

- seluruh obfuscation otomatis terbuka;

- encrypted string dapat langsung dibaca;

- downloaded content selalu tercatat;

- seluruh script selalu tersedia;

- atau Base64 selalu sudah didecode.

  

Aturan:

  

- Jangan menganggap Event ID 4104 selalu memuat `-EncodedCommand`.

- Jangan menganggap semua Base64 berasal dari PowerShell.

- Jangan menganggap semua Base64 menggunakan UTF-16LE.

- Periksa raw XML dan field aktual.

- Hasil decode tidak boleh dijalankan.

  

Workflow: temukan `-EncodedCommand` pada command line → ambil nilai

Base64 → From Base64 → Decode Text sebagai UTF-16LE → periksa hasil →

simpan TXT dan recipe → jangan dieksekusi.

  

- Recipe CyberChef: `From Base64` → `Decode text` (pilih charset

  `UTF-16LE`). Bila hasil masih bercampur karakter null/gibberish, coba

  operasi `Remove null bytes` sebelum atau sesudah `Decode text`.

- Verifikasi: hasil decode berupa teks command yang terbaca (bukan

  simbol acak); simpan hasil dan recipe ke `OUTPUT`.

- **Catatan keamanan:** salin string dari notes, jangan menjalankan

  command hasil decode — decoding hanya untuk membaca isi, bukan

  eksekusi (lihat prinsip Bagian 3 dan 24).

  

**Workflow aman:**

  

1. Copy command/data mencurigakan dari notes (bukan menjalankannya).

2. Paste sebagai text ke CyberChef.

3. Pilih recipe yang sesuai.

4. Jangan mengeksekusi hasil decode.

5. Simpan hasil decode sebagai file TXT di `OUTPUT`.

6. Catat recipe yang digunakan (urutan operasi).

7. Simpan screenshot bila diperlukan.

8. Verifikasi hasil masuk akal secara konteks (bukan gibberish).

  

**WAJIB PAHAM**

> Decoding bukan execution. CyberChef hanya mengubah representasi data,

> bukan menjalankan isinya.

## 25. Cross-Tool Verification

  

Setiap temuan penting diperiksa silang menggunakan minimal dua tool

atau dua representasi data.

  

Contoh:

  

- Event Viewer untuk melihat General dan raw XML.

- EvtxECmd untuk menghasilkan CSV.

- Timeline Explorer untuk sorting dan filtering.

- PowerShell untuk memeriksa event secara langsung.

  

- Event Viewer dan EvtxECmd dapat membaca file EVTX yang sama.

- Keduanya bukan dua source evidence independen.

- Keduanya adalah dua tool atau dua representasi dari source evidence

  yang sama.

- Cross-tool verification digunakan untuk memeriksa:

  - field;

  - timestamp;

  - EventRecordID;

  - provider;

  - message rendering;

  - hasil parser;

  - dan efek filter.

- Source evidence independen baru dianggap berbeda jika berasal dari:

  - host lain;

  - channel lain;

  - file EVTX lain;

  - Sysmon;

  - Defender;

  - network log;

  - telemetry lain;

  - atau evidence terpisah.

  

| Temuan | Source evidence | Tool/representasi pertama | Tool/representasi kedua | Hasil pemeriksaan silang |

|---|---|---|---|---|

| *(diisi saat praktik)* | | | | |

  

**Penyebab perbedaan jumlah event antar-tool:**

filter, parser, timestamp/timezone, source file berbeda, corrupt

record, event map, message rendering, hidden columns.

  

Jangan menggunakan frasa "dua sumber" untuk Event Viewer dan EvtxECmd

yang membaca file EVTX yang sama.

- Keterbatasan analisis.

- [ ] Event ID tercatat.

- [ ] TimeCreated tercatat.

## 30–31. Mini Practice Tool

  

**Prasyarat:** sediakan minimal satu file `.evtx` fiktif/sample (boleh

hasil ekspor sendiri dari Event Viewer lokal, bukan dataset Guided Lab)

sebelum memulai Tugas 4 dan seterusnya — tugas 1–3 (struktur folder,

**Membuat EVTX Latihan Aman**

  

1. Gunakan VM latihan milik sendiri.

2. Buka Event Viewer.

3. Pilih log rutin yang sudah tersedia, misalnya `System` atau

   `Security`.

4. Pilih **Save All Events As**.

5. Simpan file EVTX sementara di folder latihan.

6. Copy file tersebut ke `EVIDENCE/ORIGINAL`.

7. Hitung SHA-256 file ORIGINAL.

8. Simpan hash ORIGINAL.

9. Copy file dari `ORIGINAL` ke `EVIDENCE/WORKING`.

10. Hitung SHA-256 file WORKING.

11. Bandingkan hash ORIGINAL dan WORKING.

12. Mulai latihan hanya jika hasil perbandingan `True`.

  

Jangan menggunakan:

  

- dataset Guided Lab final;

- evidence lomba nyata;

- EVTX dari sistem produksi;

- EVTX milik orang lain tanpa izin;

- file yang berisi data sensitif.

  

**WAJIB PAHAM**

  

> EVTX latihan hanya digunakan untuk melatih membuka, memfilter,

> parsing, query, export, dan dokumentasi. Jangan menganggap isi EVTX

> latihan sebagai insiden keamanan.

  

Latihan dengan data fiktif kecil dan aman (bukan dataset Guided Lab):

  

1. Membuat folder evidence sesuai struktur Bagian 4.

2. Hash satu file.

3. Hash satu folder.

**Tugas 11 — Query dengan Get-WinEvent**

  

Command:

  

```powershell

Get-WinEvent -Path "PATH_FILE.evtx" |

Select-Object -First 5 TimeCreated, Id, ProviderName, RecordId

```

  

Expected output: lima event pertama tampil; kolom `TimeCreated`, `Id`,

`ProviderName`, dan `RecordId` tersedia.

  

Verification: cocokkan salah satu `RecordId` dengan Event Viewer;

cocokkan timestamp; pastikan source EVTX sama.

  

Common error: memakai `-LogName`; path salah; file tidak berada di

`WORKING`; file bukan EVTX valid.

  

Evidence disimpan: screenshot console; command pada notes; source

EVTX; `RecordId` yang dibandingkan.

  

**Tugas 12 — Query dengan wevtutil**

  

Command dasar:

  

```cmd

wevtutil qe "PATH_FILE.evtx" /lf:true /f:xml /rd:false

```

  

Command filter:

  

```cmd

wevtutil qe "PATH_FILE.evtx" /lf:true /q:"*[System[EventID=EVENT_ID]]" /f:xml /rd:false

```

  

- Ganti `EVENT_ID` dengan ID yang benar-benar tersedia pada EVTX.

- Periksa Event ID melalui Event Viewer terlebih dahulu.

- Jangan memaksakan Event ID 4624 jika file berasal dari channel

  `System`.

- Command belum dianggap teruji lokal sampai benar-benar dijalankan.

  

Expected output: XML event tampil; output filter hanya memuat Event ID

pilihan.

  

Verification: cocokkan Event ID; cocokkan `RecordId`; cocokkan

timestamp dengan Event Viewer.

  

Common error: lupa `/lf:true`; salah path; XPath salah; Event ID tidak

tersedia.

  

Evidence disimpan: screenshot console; command pada notes; Event ID

pilihan; source EVTX.

  

Tidak ada flag atau jawaban insiden yang diberikan pada tahap ini —

seluruh data pada tugas ini bersifat fiktif dan hanya untuk melatih

mekanik penggunaan tool.
